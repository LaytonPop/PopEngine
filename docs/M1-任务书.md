## 二、动手顺序（卡住了再看，别一上来照抄）

1. 打开 `tests/test_loop.py`，只看场景 A。把 `run()` 的最短版本写出来：
   建 `messages = [Message(role="user", content=prompt)]` → 调一次 `chat` → 如果
   `stop_reason == "end_turn"` 就 `return RunResult(...)`。跑一遍，A 绿了没？
2. 场景 B。想清楚两件事再动手：
   - `assistant` 那条消息（带 `tool_calls` 的）**必须先 append 进 messages**，再执行工具。
     为什么？（提示：tool 消息的 `tool_call_id` 指向谁？如果不先放进去，模型的视角里是不是
     凭空出现了一条"结果"？）
   - `message.tool_calls` 是**元组**，一次可能有 0 个、1 个、2 个。要用 `for` 而不是取第一个。
3. 场景 C。把上面两步放进一个"最多跑 `max_steps` 次"的循环里。想清楚：
   计数的是**模型调用次数**，不是工具调用次数。循环正常退出 = 撞到天花板 = 失败。
4. 场景 D。`try/except` 包住 `chat()`。注意：`messages` 里已经有的东西不能丢。
5. 全绿之后跑：`uv run ruff check .` 和 `uv run mypy src`。
6. 把 `loop.py` 从头到尾读一遍，确认每一行你都说得出"为什么"。说不出的地方就是明天
   面试官会问的地方。

## 三、三个必须想清楚的问题（面试会问，写不出答案就先别提交）

1. **为什么用 `stop_reason` 判断结束，而不是"看这轮有没有 `tool_calls`"？**
   （对照：很多教程就是 `if not tool_calls: break`。它什么时候会出错？）
2. **为什么 `messages` 就是全部状态？循环为什么不需要一个"当前阶段"字段？**
3. **一次要 2 个工具时，能不能只回一条 tool 消息？为什么必须在 assistant 之后、按序回填？**

## 四、三个常见坑

- **顺序错**：先执行工具再 append assistant 消息 → 第二轮 chat 里 tool 消息跑到了
  assistant 前面，模型会当成"用户提前给了结果"。
- **只处理第一个 tool call**：`response.message.tool_calls[0]`。测试 B 一次给两个，会挂。
- **把 max_steps 当成"工具调用上限"**：它限制的是模型轮数。撞上限时 `status` 是
  `failed` 不是 `ok` —— 这是有意的，永动机不是一个成功的 run。
