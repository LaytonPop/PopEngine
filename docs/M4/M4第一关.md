## 二、从表上读出的五个问题：四个插槽 + 一个契约

前四个是「缺插槽」，第五个不是 —— 它是**契约缺陷**，性质不同，所以单独列。

### 四个插槽

**问题 1（T0）· `run()` 只接一句 prompt。**
上一轮跑完的 `messages` 在 `RunResult` 里，但没有入口塞回去。所以「第 3 步被 kill、从第 4 步接着跑」在接口上根本不可能。

**问题 2（T1）· 视图和账本没分开。**
以后要压缩，唯一能改的就是 `messages` —— 而 `messages` 就是 `RunResult.messages`，就是恢复的唯一依据。**改它 = 销毁证据。**

**问题 3（T3/T6）· 消息产生没有对外事件。**
`StepEvent` 只记了「模型说了什么、工具跑了多久」，没记「`messages` 变长了」。所以磁盘上永远只有空。

**问题 4（T4）· 停止条件是硬编码的。**
现在只有两个出口写死在 `for` 里（`end_turn`、步数用尽）。想加一条「连续同参重复就熔断」，必须改 `for` 语句 —— 这是**给循环加规则**，不是**给循环加插槽**。

### 一个契约缺陷

**问题 5（T_last）· `test_l` 钉住的孤儿副作用。**
工具执行了、副作用不可逆、结果模型永远读不到。11-12 写的是「留着不修」，理由是怕破坏 loop / graph 形状一致。

## 四、解决方案：签名 + 位置 + 不变量 + 放错的症状

> 只给形状，不给实现。每一条都要自己填「为什么放这儿」和「放错了会怎样」。

### 4.1 `history`（T0）— `loop.py:84`

```python
def run(self, prompt: str, *, history: Sequence[Message] = ()) -> RunResult:
```

- **位置**：`messages = [*history, Message(role="user", content=prompt)]`
- **不变量**：`history` 里的消息**绝不触发** `on_message`。它们是刚从磁盘读回来的，再落一遍就是重复。
- **放错的症状**：续跑一次，账本长度变成 `2N` 而不是 `N+1`。（这个坑一定会踩。）

### 4.2 `before_model`（T1）— 循环内、`provider.chat` 之前

```python
BeforeModel = Callable[[int, Sequence[Message]], Sequence[Message]]
```

- **位置**：只在 `step > 1` 调（第 1 步手里只有 prompt，没有可整理的）
- **不变量**：返回值**只作为 `provider.chat` 的入参，绝不回写 `messages`**
- **放错的症状**：压缩完 `RunResult.messages` 变短 —— **证据被销毁**。这条不变量比「能压缩」重要得多。

### 4.3 `on_message`（T3 / T6）— 三处 append 之后

```python
OnMessage = Callable[[Message], None]
```

- **位置**：`:84`（user）、`:129`（assistant）、`:182`（tool）—— **三处，一个都不能漏**
- **不变量**：立刻调，不许攒批
- **放错的症状**：攒批 = 恢复点退回上一批 = 副作用可能重跑一次。这正是 P0 账本实验的结论。

### 4.4 `should_stop`（T4）— `:129` 之后、`:182` 之前

```python
ShouldStop = Callable[[int, LLMResponse, Sequence[Message]], str | None]
```

- **返回非空** → 当场返回 `failed/stopped`，**该步工具零执行**
- **不变量**：必须在**唯一有副作用的那一刻之前**
- **放错的症状**：放在工具循环之后，工具已经跑完了才喊停 —— **「拦」变成「事后通知」**。graph 那边写过同一句话：护栏必须在跑节点之前。

### 4.5 撞线禁工具（T_last）— `:89` 之后、`:95` 内

- 每步算出 `step_specs = tool_specs if step < max_steps else []`，传给 `provider.chat`
- 撞线那步若仍返回 `tool_use` → 直接返回 `failed/max_steps`，工具循环一次不跑
- 已核实：`provider.py:67` 是 `if wire_tools:`，空列表**不会**发出非法的 `"tools": []`

> ⚠️ **一个要自己拍的决定**：撞线那步如果同时命中了 `should_stop`，报 `stopped` 还是 `max_steps`？两个都是真的。
> **没有标准答案** —— 但一旦选了，必须写进 `loop.py` 的 docstring，因为日志要靠它回答「这一轮是谁喊停的」。
一旦撞线了，选择`should_stop`
