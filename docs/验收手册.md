### ④ 反向验收：四条防线 + 一条网络

把这段整块贴进 PowerShell 跑（这是唯一一段需要直接碰 Python 的，其他都是敲脚本）：

```powershell
& $py -c @"
from kama_engine.tools import ToolRegistry
from kama_engine.tools.builtin import ListDirTool, ReadFileTool
from kama_engine.types import ToolCall
reg = ToolRegistry([ListDirTool('.'), ReadFileTool('.')])
for name, kw, raw in [
    ('read_file', {'path': '../etc/passwd'}, None),
    ('read_file', {'path': 'C:/Windows/win.ini'}, None),
    ('read_file', {}, None),
    ('nope', {}, None),
    ('read_file', {}, '{\"path\": \"a.p'),
]:
    r = reg.invoke(ToolCall(id='x', name=name, arguments=kw, raw_arguments=raw))
    print(name, kw, 'raw=', bool(raw), '-> is_error=', r.is_error)
"@
```

**通过标准**：五行全部 `is_error=True`，且错误信息分别说得清是哪种错：

| 输入 | 应该报 |
| --- | --- |
| `../etc/passwd` | 路径越界 |
| `C:/Windows/win.ini` | 不允许绝对路径 |
| 缺 `path` | 缺少参数 path |
| 工具名 `nope` | 未知工具 |
| `raw_arguments` 是半截 JSON | 参数不是合法的 JSON 对象 |

**为什么这五行重要**：这五个都是"模型可能给、程序必须接住"的输入。任何一行变成 `is_error=False` 或者抛异常把 loop 炸掉，就等于模型能一句话让你的 agent 崩。

**再验一条真网络错误**（用错的 key，故意撞 401）：

```powershell
$env:KAMA_LLM_API_KEY = "sk-wrong"
& $py scripts\hello_llm.py "hi"
$LASTEXITCODE
```

**通过标准**：报 `HTTP请求失败，状态码：401`，并且**带上服务端返回的原文**（里面有 `Authentication Fails`），退出码 1。

> 验完**关掉这个终端**，或者 `Remove-Item Env:\KAMA_LLM_API_KEY`。脚本里 `.env` 是 `setdefault`，环境变量优先级更高——这既是特性也是个坑。

### ⑤ 通过之后，你要能答这三个问题

1. 为什么不用 `openai` SDK？——多一个依赖就多一层看不见的转换，面试时"HTTP 是我自己发的"更好讲。
2. 为什么 `HTTPError` 不能和"网络断了"一样处理？——4xx/5xx 是**服务器说话了**，原文在 `e.read()` 里，是唯一能看懂的线索；`URLError` 才是压根没连上。
3. 模型在**同一个回合**里同时要了 `list_dir` 和 `read_file`，loop 是怎么处理的？——两条 `tool_call` 属于**同一条 assistant 消息**，loop 依次 `invoke`、把两个结果都按 `tool_call_id` 配对塞回去，然后**再**问模型一次。

## c 轮 · 事件（`events.jsonl`）

### 要交付
每一步、每次工具调用、每次失败都落成一行 JSON；`--trace` 指定路径。

### 你跑什么

```powershell
& $py scripts\run_task.py D:\workSpace\Pop\kama-engine --trace traces\a.jsonl
Get-Content traces\a.jsonl | Measure-Object -Line
Get-Content traces\a.jsonl -TotalCount 2
```

### 通过标准（预计）
1. 文件行数能和 `RunResult.steps` 对上，不重不漏
2. 每次工具调用有 `start` / `end` 两条，且带 `tool_use_id`
3. 失败那次（`is_error=true`）也落在文件里
4. **文件里没有任何 key 片段**：

```powershell
Select-String -Path traces\a.jsonl -Pattern "sk-","Authorization" -SimpleMatch
```

> 第 4 条是红线。事件系统最容易顺手把整个 request body 记下来——那等于把 key 写进日志。

### 反向验收

```powershell
$env:KAMA_LLM_API_KEY = "sk-wrong"
& $py scripts\run_task.py D:\workSpace\Pop\kama-engine --trace traces\bad.jsonl
```

期望：`traces\bad.jsonl` 里有一条 error 事件（带状态码和原文），并且**依然没有 key**。
