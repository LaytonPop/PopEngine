## 第 1 段（约 60 分钟）：接线 + 场景 A 真跑

目标：真模型把**一问一答**走完，先不接工具。

- [ ] 新建 `src/kama_engine/llm/provider.py`，实现 `OpenAIProvider.chat(messages, tools) -> LLMResponse`
      内部顺序固定死：
      ```
      to_wire(messages) → to_wire_tools(tools) → POST /chat/completions
      → 检查 status_code → from_wire(resp.json())
      ```
- [ ] 用标准库 `urllib.request`，**不引 openai SDK**
      （理由：多一个依赖 = 多一层看不见的转换；面试时"HTTP 是我自己发的"更好讲）
- [ ] key 只从环境变量读，**任何情况下不打印**
- [ ] 写 `scripts/hello_llm.py`：一句 user 输入 → 打印 `RunResult`
- [ ] 真跑一次

> **验收物**：终端里真实打印出模型回的话 + `stop_reason: end_turn`（不是 `unknown`）
> **检查点**：「响应里 `choices` / `usage` / `system_fingerprint` / `logprobs` 这些键，哪些我用了、哪些我完全不管？为什么可以不管？」
> （答案要能接到 `from_wire` 的白名单取键）

### 这一段会踩的坑

- 忘了 `Content-Type: application/json` → 网关 400，而错误信息在 body 里，别只看状态码
- `urllib` 抛 `HTTPError` 时，`e.read()` 里才是真错误（"model not found"之类）
- `finish_reason` 为 `None` 会落到 `unknown` 分支 —— 别急着当 bug 改，先看清楚是哪种响应
- **烧钱预警**：`stop_reason` 和 `tool_calls` 对不上时（`M2-待办.md` 第 1 条）loop 会空转到 `max_steps`，
  每条都是真钱。第 1 段先别管，接了工具之后第一件要补的就是它

## 第 2 段（约 60 分钟）：真工具 + 场景 B 真跑

目标：真模型 + 真工具，跑通一次**多次工具往返**。

- [ ] `src/kama_engine/tools/builtin.py`：`list_dir(path)` / `read_file(path)`
      - 两个工具必须**锁在指定根目录内**：`Path(root, path).resolve()` 后校验还在 root 下面
        （`is_relative_to`）。越界**返回 `is_error=True` 的结果，不抛异常**
      - `read_file` 超过 N 行截断，并在 content 末尾明确写「已截断，共 M 行」——
        模型必须能看见"我被截断了"这件事
      - 参数用 JSON Schema 写进 `ToolSpec.parameters`，**不是 docstring**
- [ ] 真跑：让它读这个仓库的 README，用一句话说这项目干嘛的

> **验收物**：trace 里至少两轮工具往返，且是**模型自己**决定先 `list_dir` 再 `read_file`
> **检查点**：「为什么工具参数要写 JSON Schema 而不是 docstring？」
> 「越界路径返回 `is_error=True` 而不是抛异常，这是谁的决定？」（→ 接回 M1 的 `ToolRegistry.invoke()` 契约）
